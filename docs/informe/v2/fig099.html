Base de datos TiDB Cloud: mapa de tablas por bounded context

Tabla con borde continuo: owner_admin_id con FK a users.id · borde punteado: sin esa FK · → clave foránea · ⇢ referencia por id sin FK

usersbuilding_membersmember_invitations

building_members → users (owner_admin_id, user_id)

buildingsprofiles

4. Billing (genérico)

Leyenda

■ core · ■ soporte · ■ genérico
users (IAM): cuenta del condominio; owner_admin_id la referencia desde los demás contextos.
Vista resumida: solo nombres de tabla y relaciones. Las columnas, tipos, claves e índices de cada tabla se detallan en los diagramas de base de datos por contexto del Capítulo V (Figs. 107, 110, 113, 116, 119, 122, 125, 128 y 131). En las tablas con borde punteado, owner_admin_id es VARCHAR(128) con el external_id del condominio, sin FK (salvo maintenance_checkouts: INT sin FK). resident_ai_usages la crea SchemaUpgrade (SQL), sin entidad EF.
